# LUMIO — 2단계 인증이 있는 웹 서비스

정보보호관리 팀 프로젝트 **「AiTM 피싱, 직접 뚫고 직접 막다 — 중간자 공격 구축과 AI 기반 방어기법 검증」** 의
실습 환경에서 **공격 대상이 되는 정품 웹 서비스**입니다.

AiTM(중간자 중계) 공격을 제대로 실험하려면 중계할 가치가 있는 진짜 서비스가 먼저 있어야 합니다.
그래서 회원가입부터 2단계 인증, 계정 복구까지 실제 서비스 수준으로 직접 만들었습니다.

> ⚠️ **교육·연구 목적의 실습용 코드입니다.** 격리된 가상 네트워크에서만 동작하도록 만들었고,
> HTTPS 미적용 등 실제 운영에 필요한 요소가 빠져 있습니다. 그대로 인터넷에 올리지 마세요.

---

## 무엇이 들어 있나

```
web/             정품 웹 서비스 (PHP + SQLite)
authenticator/   휴대폰 인증 앱 시뮬레이터 (단일 HTML)
deploy/          배포 스크립트 · Apache 설정 · 운영 CLI
```

## 1. 웹 서비스 (`web/`)

**스택**: Apache 2.4 + PHP 8.1 + SQLite · 외부 라이브러리 없음

### 인증 흐름

```
회원가입 ──> OTP 비밀키 + 백업 코드 8개 발급
   │
로그인 ──> ① 비밀번호 ──> ② TOTP 6자리 ──> 인증된 세션
                             └── 또는 백업 코드
```

| 파일 | 역할 |
|---|---|
| `index.php` | 로그인 후 홈 (카드 그리드) |
| `login.php` | 1단계 — 아이디·비밀번호 |
| `otp.php` | 2단계 — TOTP 6자리 / `?mode=recovery` 로 백업 코드 |
| `signup.php` | 회원가입 + OTP 비밀키·백업 코드 발급 |
| `settings.php` | 설정 — 개인정보 / 로그 / 보안 / 계정 삭제 |
| `saved.php` | 아카이브 |
| `success.php` | 인증 완료 확인 (세션 ID·출발지 IP 표시) |
| `lib/totp.php` | **RFC 6238 TOTP 순수 PHP 구현** |
| `lib/db.php` | SQLite 스키마 · 접속 로그 · 백업 코드 · 유예 삭제 |
| `lib/common.php` | 세션 · CSRF · 공통 레이아웃 |

### 보안 설계

1. 비밀번호는 `password_hash()` 해시 저장 — 평문 없음
2. **2단계 강제** — 1단계만 통과한 세션은 보호 페이지에 접근할 수 없음
3. OTP 성공 시 `session_regenerate_id(true)` — 세션 고정 공격 방어
4. DB 를 웹 루트 **밖**(`/var/lib/sunrinns/app.db`)에 배치
5. `/lib` 디렉터리 웹 접근 차단 (`Require all denied`)
6. 상태 변경 요청에 **CSRF 토큰** 검증
7. 비밀번호 변경 시 세션 ID 재발급 — **이미 탈취된 세션을 무력화**
8. 접속 로그에 `REMOTE_ADDR` · `X-Forwarded-For` 기록

### 잠기지 않게 하는 두 가지 장치

실제로 써 보니 계정이 영영 잠기는 막다른 길이 두 군데 있어서 둘 다 막았습니다.

- **백업 코드** — OTP 기기를 잃으면 재설정 화면에 들어갈 방법이 없습니다.
  가입 시 일회용 코드 8개를 함께 발급하고(해시 저장, 1회용), 2단계 화면에서 OTP 대신 쓸 수 있게 했습니다.
- **유예 삭제** — 삭제를 눌러도 즉시 지우지 않고 `deleted_at` 에 예약만 남깁니다.
  7일 안에 다시 로그인하면 복구할 수 있습니다. 감사 기록은 삭제해도 남깁니다.

### 깔끔한 URL

`mod_rewrite` 양방향 규칙으로 주소에 `.php` 가 보이지 않습니다.
`/login.php` → **301** → `/login`, 확장자 없는 경로는 내부적으로 `.php` 로 매핑합니다.

## 2. 인증 앱 시뮬레이터 (`authenticator/`)

피해자가 OTP 코드를 확인하는 **휴대폰 인증 앱** 역할을 하는 단일 HTML 파일입니다.

- **순수 JavaScript 로 TOTP 를 계산**합니다. Web Crypto 를 쓰지 않아 `file://` 로 열어도 동작합니다.
- 계정을 여러 개 등록할 수 있고, 남은 시간이 링으로 표시됩니다.
- 브라우저에서 바로 열면 됩니다. 서버가 필요 없습니다.

> 이 앱을 **피해자 기기 안**에 둔 것은 의도된 설계입니다.
> OTP 생성기가 네트워크 어디에서도 코드를 받아오지 않으므로, 공격자는 비밀키를 훔칠 수 없고
> **피해자가 입력한 6자리를 실시간으로 중계**하는 수밖에 없습니다.
> 이것이 AiTM 이 2단계 인증을 넘는 방식이고, 동시에 **FIDO2 는 왜 안 뚫리는지**(도메인 바인딩)로 이어집니다.

## 3. 배포 (`deploy/`)

Ubuntu 22.04 기준입니다. 대상 서버에서 root 로 실행합니다.

```bash
bash deploy/setup_web.sh
```

Apache + PHP + SQLite 설치, 소스 배포, 권한·vhost 설정을 한 번에 합니다.

### 운영 CLI

웹 화면으로는 풀 수 없는 상황(OTP 비밀키와 백업 코드를 둘 다 잃어버림 등)을 위한 안전망입니다.

```
sunrinns-admin list                 계정 목록 (상태·남은 백업코드)
sunrinns-admin show      <아이디>   상세 + 현재 OTP 코드
sunrinns-admin restore   <아이디>   삭제 예약 취소
sunrinns-admin reset-otp <아이디>   새 OTP 비밀키 발급
sunrinns-admin codes     <아이디>   새 백업 코드 8개 발급
sunrinns-admin purge                유예 기간 지난 계정 실제 삭제
sunrinns-admin seed                 실습용 기본 계정 보장
```

> `seed` 가 만드는 계정은 **실습용 고정 비밀번호**를 씁니다. 격리된 실습 환경 전용입니다.

## 이 서비스가 프로젝트에서 한 역할

이 서비스를 상대로 **AiTM(중간자 중계) 공격을 직접 구축해 실제로 뚫었습니다.**

- 공격자가 DNS 를 위조해 트래픽을 자기 쪽으로 끌어온 뒤, 정품 서버로 **그대로 중계**합니다.
- 피해자는 **정품 도메인**에서 **정상적으로** 로그인에 성공합니다. 이상을 느낄 단서가 없습니다.
- 중계 페이지는 원본과 **md5 가 동일**합니다 — 콘텐츠만 보는 탐지기는 구별할 수 없습니다.
- 공격자는 비밀번호·OTP 6자리·백업 코드는 물론 **2단계 인증이 끝난 세션 쿠키**를 가져갑니다.
  그 쿠키 하나로 **비밀번호도 OTP 도 입력하지 않고** 계정에 들어갑니다.

> **MFA 를 깬 것이 아니라 건너뛴 것입니다.**
> MFA 는 로그인할 때 신분을 확인하는데, 공격자는 로그인을 하지 않습니다.
> 이미 인증이 끝난 결과물을 들고 들어옵니다.

현재는 **이것을 무엇으로 막을 수 있는지** 방어기법을 하나씩 적용하며 검증하는 단계입니다
(쿠키 속성 강화 → 세션-출발지 바인딩 → HTTPS → FIDO2/WebAuthn → AI 기반 세션 이상 탐지).
방어 적용에 따른 코드 변경은 이 저장소에 계속 반영됩니다.

> 공격 쪽 구성(중계 서버·수집기·실시간 감시 도구)은 공개 저장소에 올릴 성격이 아니라 제외했습니다.
